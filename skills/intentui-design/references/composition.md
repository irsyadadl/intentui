# Compose a premium v4 page

Convert the request into sections, required data/actions and layout constraints. Reuse the consuming application's shell/router. Use [block discovery](blocks.md) to find complementary actual catalog resources; avoid duplicate navigation, incompatible type scales and unnecessary dependency replacement.

Analytics can combine navigation, statistic Cards, Charts, a filtered Table and billing details. Settings can combine Tabs, Fieldset sections, validation, Save actions and feedback. Marketing can combine hero/features/proof/pricing/FAQ/CTA sections. Commerce can combine product/filter collections, details/cart and checkout forms. Select only sections needed for the user's functions/design direction.

Inspect local v4 APIs and selected block files before adapting them. Wire real queries/actions/routing, loading/empty/error/success states, selection and form validation. Maintain semantic colors, light/dark states, consistent spacing, heading hierarchy and content density. Check small-screen navigation and overflow, keyboard/focus, accessible names and chart summaries. Preserve deliberate brand choices.

A candidate's preview does not prove route/data correctness or responsiveness in the consuming shell. Verify the finished integrated page through TypeScript/build, existing tests and appropriate browser interaction checks. Report what was actually tested. Custom additions remain custom, not an official premium resource.
