# Patterns

Find the relevant composition or interaction in the official Design Intent UI catalog and the user's purchased resources. Patterns guide field layouts, contextual actions, navigation, empty states, and responsive behavior. Read the consuming project's v4 APIs before adapting a pattern.

A pattern is not automatically an independent registry item. Use the documented install address only when its page or authorized registry catalog provides one. Otherwise follow the authorized view/download/copy workflow for that resource, preserving its license. Do not infer a registry name from a page slug or expose purchased source in public skills. Confirm available categories from [Design Intent UI](https://design.intentui.com).

Design resources target v4 only. Verify the selected resource against local v4 exports/tokens; flag stale v3 payloads instead of producing a v3 variant. For registry-installable resources @irsyad includes public component dependencies, so do not require a duplicate @intentui namespace. Formats requiring downloads retain their separate authorized workflow.
