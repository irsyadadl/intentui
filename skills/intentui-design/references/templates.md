# Templates and starter kits

Verify the selected resource's official documentation and entitlement. Templates and commercial Next.js/Laravel starter kits can require authorized repository access or downloads, dependency installation, environment setup, and backend services. They are not all registry items. Follow each resource's actual instructions, preserving existing application structure and secrets.

The [Basic Next.js starter kit](https://design.intentui.com/docs/starter-kits/basic-nextjs) documents `create-next-app` with the public `irsyadadl/starter-kit` example. That public base does not grant access to premium blocks; @irsyad authentication is still required. Read [Next.js starter kit](https://design.intentui.com/docs/starter-kits/nextjs) or [Laravel starter kit](https://design.intentui.com/docs/starter-kits/laravel) for those products. Do not clone a starter into an existing application root or substitute a public base for a purchased template without an explicit resource choice.

For integration, inspect routes, adapters, auth/session conventions, assets, CSS, and component dependencies. Keep resource downloads and proprietary source out of public skill examples. Do not invent starter/template shadcn addresses.

Design resources target v4 only. Verify the selected resource against local v4 exports/tokens; flag stale v3 payloads instead of producing a v3 variant. For registry-installable resources @irsyad includes public component dependencies, so do not require a duplicate @intentui namespace. Formats requiring downloads retain their separate authorized workflow.
