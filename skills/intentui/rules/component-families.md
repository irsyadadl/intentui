# Choose a component family

Use this decision guide when selecting components, not for every small edit. Names below are verified in both upstream branches unless a difference is noted. Installed customized source remains authoritative. Read only the relevant family reference and examples under `src/components/examples/` on the detected [3.x branch](https://github.com/irsyadadl/intentui/tree/3.x/src/components/examples) or [4.x branch](https://github.com/irsyadadl/intentui/tree/4.x/src/components/examples). Use registry/MCP examples only after matching their version.

| Family               | Prefer / when                                                                                                                                         | Avoid / common mistake                                                                                          | Composition and accessibility                                                                                                                                           | Version/detail route                                                                          |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Actions              | Button for mutations/submission; Link for navigation; ButtonGroup for related actions                                                                 | Button with href invented from another system; link for destructive mutation; variant/asChild copied from Radix | supported intent/size, onPress, pending/disabled; label icon-only controls; explicit submit type                                                                        | inspect button/button-group/link exports; [components](components.md)                         |
| Typography/content   | Heading for hierarchy; Text with TextLink/Strong/Code; DescriptionList for paired values                                                              | choosing heading level solely for font size; clickable span; invented TextLink import from link module          | correct heading level, link destinations and readable text; semantic HTML remains valid                                                                                 | heading/text/description-list examples; tokens differ by version                              |
| Forms                | TextField/Input, NumberField, CheckboxField/Checkbox, RadioGroup/RadioField/Radio, SwitchField/Switch, Select, ComboBox, DatePicker                   | state/name on button primitives instead of Fields; JavaScript Date for DateValue; placeholder as only label     | Fieldset/Legend, visible Label, Description/FieldError, validation and controlled state from installed types                                                            | [forms](forms.md); inspect older customized React Aria integrations                           |
| Navigation           | existing SidebarProvider/Sidebar composition or NavbarProvider/Navbar; Tabs for views within a section; Breadcrumbs for hierarchy                     | creating a second shell; tab for unrelated route without adapter; assuming TabsTrigger exports                  | TabList with Tab IDs and matching TabPanel/TabPanels; current-page state; keyboard and mobile navigation                                                                | navbar/sidebar/tabs examples; their internal v4 overlay dependencies changed                  |
| Dialogs/overlays     | Dialog/Sheet for focused overlay tasks; Menu for action collections; Popover for floating content; Tooltip for supplemental help                      | tooltip for essential action/info; new modal Dialog inside a Popover; old content/trigger role assumptions      | named surface, focus management, dismissal/close, reachable triggers; Button inside v4 wrappers; v4 TooltipTrigger wraps Button + Tooltip (v3 Tooltip + TooltipContent) | [overlays](overlays.md), then only the detected version's overlay file                        |
| Data collections     | Table for comparable rows/columns; ListBox for selectable options; GridList for rich/actionable rows; Tree for hierarchy; TagGroup for tags           | table as layout; missing stable IDs/textValue; Select state props applied to collections                        | TableHeader/Column and TableBody/Row/Cell; named collections, row headers, selection and sorting wiring                                                                 | [collections](collections.md); Menu surface differs by version                                |
| Feedback/status      | Note for inline feedback; Badge for compact status; Toast with project's sonner calls for transient completion; ProgressBar/Meter for measured values | using a toast as the only persistent form error; assuming Alert or toast exports from another library           | meaningful status text and live-region behavior; Toast is the local renderer, inspect app placement/call API; ProgressBarHeader/Value/Track as needed                   | note/toast/progress-bar/meter examples; semantic foreground names change                      |
| Charts/visualization | AreaChart/LineChart/BarChart or other installed chart wrapper; Chart with its tooltip/legend exports for custom charts                                | decorative chart instead of comparable table; fabricated dataKey/series props; inaccessible color-only meaning  | verify wrapper's data/category schema, legend/tooltip, container dimensions, summary/table alternative and empty dataset                                                | chart families and actual `.tsx` props; no automatic component upgrade                        |
| Layout               | existing Container, Card/Header/Content/Footer, Separator, ScrollArea and shell structure                                                             | recreating a supported surface; using scroll area for all content; arbitrary spacing rewrites                   | use semantic main/section/nav where appropriate; responsive widths/gaps, overflow and focus visibility                                                                  | v4 Card uses --card-spacing; older source may use --gutter; inspect rather than global rename |
| Loading/empty        | Skeleton for content-shaped placeholders, Loader for pending action, Note/Text/action for empty/recoverable error                                     | fake progress number; indefinite busy state without name; inventing Empty export                                | differentiate initial loading, no data, filtered no-results and error; aria-busy/status where appropriate; actionable recovery                                          | inspect loader/skeleton; no dedicated Empty required or assumed                               |
| Search/commands      | SearchField/SearchInput for query; CommandMenu/Search/List/Item for action navigation                                                                 | replacing full search results with a command palette; adding global shortcut handlers on every render           | label search, stable command IDs and textValue, intentional shortcut/focus lifecycle; installed controlled props                                                        | search-field/command-menu examples; internal menu/popover dependencies must match version     |

For current props, read the local exported interface and matching example, or view the selected registry item. No table row grants permission to change unrelated components. A page request should also read [composition](composition.md); a simple Button change does not need that file.
